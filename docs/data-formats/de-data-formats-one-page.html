BThree table formats

Reliability around a collection of files

All three add ACID transactions (safe, consistent commits), schema evolution and time travel to retained versions, through compatible engines.

Delta Lake

Parquet data + _delta_log transaction history

Strong fitBatch + streaming tables and updates. Common in Spark, Databricks and Fabric.

Trade-offCheck reader protocol / feature support. Plan retention and file maintenance.

Apache Iceberg

Parquet / ORC / Avro + snapshot metadata

Strong fitMulti-engine tables. Field IDs and partition evolution support safe changes.

Trade-offCatalog / commit coordination and snapshot maintenance. Check engine features.

Apache Hudi

Columnar base files + timeline; optional logs

Strong fitFrequent upserts, change data capture (CDC), and incremental processing.

Trade-offCopy-on-write rewrites files; merge-on-read merges logs. Tune compaction, keys and indexes.

Use a table-aware reader: raw-file reads can ignore deletes or include obsolete versions. Cleanup can remove time-travel history; it is not a permanent backup.

Pipeline stages: bronze = raw; silver = cleaned; gold = business-ready. These are quality stages, not fixed format rules.

Fabric: keep source formats in bronze when useful; use Delta tables for silver and gold. Parquet is their underlying data format.
